# 继续开发（给人，也给 AI）

固件 **1.1.4**，ESP-IDF **v5.2.3**，LVGL **v8.3**。当前板是 M5Dial。满 16 表时北向大约 13 秒一轮。本文只说明代码怎么分层、换屏改哪里、哪些事实不能改。

## 分层

从上到下，改一层不要把下层细节抄进上层。

| 层 | 文件 | 只做什么 |
| --- | --- | --- |
| 板级 | `main/board_m5dial.h` | 引脚、分辨率、MADCTL、电源保持脚 |
| 面板驱动 | `main/gc9a01.c` | SPI、上电序列、`gc9a01_flush` |
| 界面 | `main/ui_task.c` 与 `ui_overview.c` / `ui_detail.c` / `ui_sysinfo.c` / `ui_setup.c` | LVGL 页面。只有 `ui_task` 可以调 `lv_*` |
| 输入 / 蜂鸣 | `encoder.c`、`buzzer.c` | 读旋钮、鸣叫。引脚来自板级头文件 |
| 南向 | `ble_scanner.c`、`crypto.c`、`meter_store.c` | 被动扫描、CCM、16 槽快照 |
| 命令 | `cmd_dispatch.c` | GATT、HTTP、MQTT `cmd` 共用一套 JSON |
| 北向 | `mqtt_client.c`、`http_server.c`、`sys_task.c` | MQTT、可选网页、Wi-Fi |

`app_main` 第一行可执行代码必须拉高 `BOARD_PWR_HOLD_GPIO`。前面不能加日志或延时。

## 换一块 S3 屏

1. **还是 GC9A01、还是 240 圆屏，只是排线不同**：只改 `main/board_m5dial.h`。改完看文字是否正立；偏色说明 MADCTL 的 BGR 位（bit3）丢了。
2. **还是圆屏，分辨率变了**：改 `BOARD_LCD_W` / `BOARD_LCD_H`，再改 `main/ui_task.h` 里的边距。页面按 240 圆的安全区排过，换分辨率要重看四角是否被裁。
3. **控制器不是 GC9A01**：换掉 `gc9a01.c` 的初始化序列。`app_main` 仍调用 `display_init()`，`ui_task` 仍把 `gc9a01_flush` 当作 LVGL flush。不要把新屏的寄存器写进页面文件。

旋钮、蜂鸣器、电源保持脚也在同一个头文件里。业务代码里不要再写死 GPIO 号。

## 不要改的事实

- 电表匹配只靠 12 位 SN + 32 hex `broadcast_key`。地址是会变的 RPA，**不要按 MAC 匹配**。
- Nonce 是 `8×0x00 ‖ BE32(counter)`。counter 空中是小端，放进 nonce 要逐字节写成大端。
- 广播里没有 PF。界面保持 `PF --`，MQTT `data` 不要加 PF 字段。
- 内部功率是 kW，MQTT `data` / `summary` 上报时 ×1000 变成 W。HTTP `get_meters` 仍是 kW。
- 满 16 表时 MQTT **一块一块发**，每块至少隔 800 ms，一轮大约 13 秒。这是为了和 BLE 扫描共存，不是漏包。日志时间是电脑收到 MQTT 的时间，不是电表上电时间。
- MQTT 连上后先停扫大约 6 秒再开扫，整段暂停不超过 12 秒。稳定后无线电偏向 Wi-Fi：扫描窗口约 37.5%（间隔 80 ms / 窗口 30 ms），约 3.5 秒扫描、1.5 秒让给 Wi-Fi。系统页在这段让出时 BLE 仍显示 ON。不要在连上的同一瞬间恢复扫描，也不要把 Wi-Fi 时隙显示成 BLE OFF。
- 不要 `erase_flash`，除非明确要清空 Wi-Fi 和表名单。
- 样机无 PSRAM。不要打开会占 PSRAM 的显示缓冲。

## 别人用 AI 接着改时

把本文件和上面四份协议文档一起交给 AI。改动限制在对应层。改完用现有工程编译：

```bat
idf.py build
idf.py -p COMx flash
```

按那台电脑设置 `IDF_PATH` 和串口。不要 `erase-flash`。

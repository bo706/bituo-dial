# Phase0~3 挂起项清单（不阻塞 Phase4）

日期：2026-09-03  
说明：下列项代码侧已按当前协议落地，或明确不属于广播路径。缺的是现场条件，不是 Phase4 北向代码的前置。

---

## 1. 非零电流 / 功率 / 电能（I / P / FE / RE）

- **缺什么条件**：测试表二次侧接已知真实负载。当前开路，15B 明文后 13 字节为 0，解析输出 0 与 APP「电流 0」一致，不是 bug。
- **怎么触发**：给 SDM01_3PN（SN `C85024E851F1`）二次侧加已知负载；硬复位 Dial，抓 12s 串口。
- **验收标准**：`PARSE phN:` 中 I、P(kW)、FE/RE 与手机 APP 同表误差 < 1%；电压仍约 220V。负功率需反向送电场景，离线 int24 roundtrip 已过（`tools/plain15_selftest.py`）。
- **不阻塞 Phase4**：是。MQTT/HTTP 上报 0 与真实开路一致。

## 2. 多表并发与列表位移

- **缺什么条件**：第 2 块物理电表 + 该表自己的 `broadcast_key`。架构已支持 16 槽；单表时概览选中 / 详情切表恒为 index0，屏无位移属正常。
- **怎么触发**：`dial_config.py --ble "BitUo-Dial" add-meter` 写入第二块表的 SN + key（匹配不靠 MAC）。旋转编码器。
- **验收标准**：概览出现两行，`>` 随旋钮在两行间移动；详情页标题为 `(1/2)` / `(2/2)`；两表 `DECRYPT OK idx=0/1` 不串数据。≥8 表并发同理，有多少验多少。
- **不阻塞 Phase4**：是。禁止用假数据在 UI 演示多表。

## 3. 功率因数 PF

- **缺什么条件**：广播 §9.3.1 的 15 字节**没有 PF**。需走电表 GATT 读特征（后续阶段），与 Dial 北向 GATT 配置通道不是同一条链路。
- **怎么触发**：实现电表侧 GATT 读特征客户端之后才能取。
- **验收标准**：UI 在拿到真实 PF 前保持 `PF --`；JSON 中 `overall_power_factor` 未测得时留空 / 不展示为实测 0。严禁从广播臆造。
- **不阻塞 Phase4**：是。上报时 PF 省略或 `null`。

## 4. UI 演示录像

- **缺什么条件**：MADCTL `0x88` 已写死，二次烧录后三页正立已确认（USB 为上）。还差正式演示录像；最好再有第 2 块表以展示列表滚动。
- **怎么触发**：方向定死后短按翻三页、旋转、（可选）断电表复现离线色。
- **验收标准**：任务书 Phase3 交付物：含编码器操作与离线警告的录像。
- **不阻塞 Phase4**：是。

## 5. 24 小时稳定性与内存泄漏长测

- **缺什么条件**：已开工。见 `docs/phase5_soak_20260904.md`；电脑勿休眠。
- **怎么触发**：连续上电 24h，`tools/soak_poll.py` 每 5 分钟打 `/api/info`。
- **验收标准**：无 panic、无 watchdog 超时、无内存泄漏（任务书 11.5）。
- **不阻塞 Phase4**：是。属 Phase5。
